# 端到端双讲回归（C++ 生产管线）

本文件记录通过 `build/double_voice.exe` 批量离线模式跑的端到端双讲回归结果。
设计背景见 [DESIGN.md](DESIGN.md) 第 6 节，判定代码 `scripts/run_regression_cell.py`。

## 测试方法

- **样本**：各测试集 `labels.jsonl` 中含双讲重叠区间（`overlap_frames` 非空）的前 200 条，
  与历史 python 评估（`scripts/eval_pvad.py --e2e`）相同的样本集与选取逻辑
- **管线**：C++ 生产路径（`double_voice --batch-list`，单进程批量，模型只加载一次），
  与 `--wav` 离线模式语义一致：（**每个文件一个全新 Denoise** 的整段预降噪）→ 整段
  fbank+PVAD 预计算 → 逐帧 silero VAD（speech-end 复位门控）→ PvadGate 扫描
  （注：qt_demo auto-test 曾误用跨文件共享的 Denoise 实例导致残态污染，已修为
  每文件新实例，与 CLI/batch 语义一致）
- **enrollment**：`enroll --batch-jsonl` 批量现场注册（CAM++ 一次加载，每条 enrollment
  wav 提 embedding 存 v3 模板），与历史 C++ 评估"每条现场 enroll"语义一致
- **判定**：confirm=2 迟滞（P(target)>0.5 连续 2 帧触发，<0.3 清零）；触发帧落在重叠区
  ±20 帧或触发帧标签为 2 = 正确；未触发 = 漏打断；否则 = 误打断
- **C++ vs python 路径差异注释**：enrollment 走 C++ fbank+CAM++ 现场注册（python 用
  预计算 .npy）、GRU 数值路径、模板仅含正质心（无负模板/cohort 参与 pvad 判决），
  几个百分点的系统性差异属正常

## 与历史 python 评估对照

| 数据 | 漏打断 | 误打断 | 正确率 |
|---|---|---|---|
| python v3 干净（500 条） | 0.6% | 7.0% | 92.4% |
| **C++ v3+rnnoise 干净（200 条）** | 0.5% | 4.0% | **95.5%** |
| python v3 增广（500 条） | 0.2% | 21.6% | 78.2% |
| **C++ v3+rnnoise 增广（200 条）** | 1.0% | 20.0% | **79.0%** |
| python v2 增广（参考） | 0.2% | 18.0% | 81.8% |
| C++ 双讲 50 条存档（v1 模型，干净） | 2.0% | 10.0% | 88.0% |

简评：

- **v5（离线默认）增广历代最佳**：C++ 增广 84.5%（误打断 15.0%，v4 为 82.5%/16.0%），
  对照 python 89.4%/10.0% 差 −4.9pp（略出 ±3pp 边缘；n=200 时两侧 95% CI 重叠，
  且 v5>v4 的相对排序一致。单 token 回退对照跑为 86.0%/13.0%，说明多 token 在 C++
  路径下未额外获益，差异主要来自数值路径）；干净 95.0% 对照 python 93.0% 差 +2.0pp（线内）。
  v5 行由含 tokens 的 v4 模板驱动（enroll --batch-jsonl 同步产出 tokens）；
- **v4 两条件（历史行）**：干净 97.5%（误打断 4.0%→1.5%）、
  增广 82.5%（误打断 21.6%→16.0%，超过 v2 的 81.8% 参考线），与 python 侧 v4 双优
  （94.0%/83.0%）及另一独立 C++ 复现完全一致，验证默认加载确为 v4；
- 干净条件 v3 C++ 95.5% **高于** python 92.4%（+3.1pp），主要来自误打断更低
  （4.0% vs 7.0%）——路径差异（enrollment 现场注册、数值路径）在正常范围内；
- 增广条件 C++ 79.0% ≈ python 78.2%（+0.8pp），误打断 20.0% vs 21.6%，基本一致；
- v3 在增广上略输 v2 模型（python 对照 78.2% vs 81.8%）的历史结论在本轮 C++ 网格中
  同样成立（79.0% vs v2 的 81.8% 参考线），与"强噪声/混响可试 v2"的模型选择指南一致；
- 两格均明显高于告警线（干净 <85%、增广 <70%），**无异常项**；
- 与 30 条增广抽验（0.800）一致，样本量放大到 200 后结论稳定。

## PVAD 同集对照：tse pvad_direct_v3 vs 当前 v7b_stream（2026-11-12）

复现：`python scripts/compare_tse_pvad.py --max-n 200`；明细 `build/pvad_compare_tse.json`。
每条件使用当前测试集前 200 条双讲（A+B 注册 A / 同一音频错误注册 C）及前 200 条纯负
（only B 注册 A）。direct_v3 保持发布阈值 TH=0.31/UNC=0.3；v7b 为 EMA-CMVN 注册先验、
P>0.5、confirm=2、hyst=0.2，不加 VAD/warm-up。direct_v3 原 F 盘 direct_scene_v2 不在
本机，以下是**当前单麦部署域**结果，不能与其官方阵列集 95.2/70.2/95.8 直接混比。

| 条件 | 模型 | A 放行↑ | 错注册 C 关闭↑ | only B 关闭↑ | 当前双讲 e2e 正确↑ |
|---|---|---:|---:|---:|---:|
| 干净 | direct_v3 TH=0.31 | 72.5% | **78.5%** | **68.5%** | —（句级模型不报帧判定） |
| 干净 | v7b_stream | **99.0%** | 1.5% | 11.0% | **84.0%**（漏1/误15） |
| 增广 | direct_v3 TH=0.31 | 64.0% | **70.5%** | **71.0%** | — |
| 增广 | v7b_stream | **90.0%** | 18.0% | 15.0% | **65.0%**（漏10/误25） |

direct_v3 阈值扫描（同一明细离线复算，不重跑模型）：

| TH | 干净 A/C/B | 增广 A/C/B |
|---|---|---|
| 0.00 | 97.0% / 12.0% / 18.5% | 95.5% / 13.0% / 21.0% |
| 0.10 | 89.5% / 33.0% / 35.0% | 88.5% / 24.0% / 38.5% |
| 0.20 | 85.0% / 55.5% / 51.0% | 81.0% / 45.5% / 54.5% |
| 0.31（发布） | 72.5% / 78.5% / 68.5% | 64.0% / 70.5% / 71.0% |

结论：**实时打断继续用 v7b_stream，不直接换 direct_v3**。direct_v3 在发布阈值下负样本
拦截显著更强，但当前域漏掉 27.5%/36.0% 的 A，且首判需 3s，定位是 TSE 前的句级放行/
关闭门控；v7b 是 10ms 帧级打断，A 召回与触发时序更适合 barge-in。若用于允许 3s 延迟的
ASR 二级复核，direct_v3 有拦截价值，但必须在当前域重新标定（TH≈0.1 时 A 召回约 89%，
负拦截仍高于 v7b），不能照搬官方阈值或直接替换。

### Qt demo 集成复测（direct_v3 TH=0.0）

已将 `direct_v3.onnx`（FP32，未量化）接入 `Engine::finalizeCollect`：v7b 触发后，3s 窗/1s
hop 提取原始电平 deep-192，TH=0.0/UNC=0.3 复核；关闭只丢弃本次 TSE/ASR，不撤销已发生的
用户打断，异常/不确定均放行。注册引用从原 wav 懒计算，新增/清空注册会失效重建。

放行；PVAD 仍在 2.45s 触发；AGC active RMS 0.08384→0.04528；ASR 输出“下不要再播放了
我有话要说”；故事泄漏 0.016（混合对照 0.359）、目标召回 0.429，**ALL PASS**。
`--auto-test`、`--persist-test`、`--agc-test` 同步通过。
