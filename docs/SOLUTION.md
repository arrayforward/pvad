# AI 语音对话"降噪"方案：基于 PVAD 的说话人门控打断

> 一句话：让用户感觉"没有噪音"的本质，不是把噪声抹掉，而是让 AI **只对用户本人的声音做出反应**——旁人说话、环境噪声、AI 自己的 TTS 声音，统统不会触发任何行为；只有用户开口，才能打断。

## 1. 问题定义：AI 语音对话里的三类"噪音"

| 干扰类型 | 典型场景 | 传统方案的痛点 |
|---|---|---|
| **环境底噪** | 风扇、空调、电流声、街道声 | 传统降噪可解，但会损伤语音细节 |
| **旁人说话（双讲）** | 家人交谈、电视人声、办公室背景 | 降噪无效（人声不是"噪"）；声纹滑窗比对在双讲时被污染，漏打断率高达 64.8% |
| **TTS 自身回声** | AI 播放的语音经扬声器回收到麦克风 | 传统依赖 AEC（回声消除），播放/采集参考时钟对齐是工程血泪，漂移即失效 |

用户的真实诉求不是 audiophile 级的干净音频，而是**行为层面的安静**：

- AI 说话时，旁边有人聊天、电视在响 → AI 不受干扰，继续说
- AI 自己的声音回荡在房间里 → 不会"自己打断自己"
- 用户本人一开口 → AI 立刻停下听用户说（150–300ms 内）

## 2. 方案总览：三层过滤漏斗

```
麦克风输入
    │
    ▼
┌─────────────────────────────────────────┐
│ 第一层：RNNoise 物理降噪                   │  平稳底噪（风扇/空调/电流）直接消除
│ 10ms 帧流式，CPU 开销 0.6%                │
└─────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────┐
│ 第二层：PVAD 目标说话人帧级判别（核心）      │  "人声级"干扰（旁人/TTS/电视）语义过滤：
│ CAM++ 声纹注册 → 多帧 token               │  每 10ms 帧判定"是不是注册用户在说话"
│ 交叉注意力 + FiLM 双条件调制 GRU           │  ——而不是"有没有声音"
└─────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────┐
│ 第三层：门控迟滞决策                       │  P(目标) 连续超阈值才触发，防抖
│ confirm=2 迟滞 + warm-up                 │  输出唯一动作：打断 / 不打断
└─────────────────────────────────────────┘
    │
    ▼
打断事件 → 停止 TTS 播放 → AI 倾听用户
```

三层各管一段，互补不重复：

- **第一层管"非人声"**：稳态噪声在信号层面抹掉，减轻后级压力
- **第二层管"人声"**：这是本方案的核心。传统 VAD 只回答"有没有人说话"，PVAD（Personal VAD）回答"**是不是这个人在说话**"——旁人、电视、TTS 合成音在帧级就被判为"非目标"，天然免疫
- **第三层管"决策稳定性"**：单帧误判不可避免（模型 FAR 残余），迟滞确认保证最终行为不抖动

## 3. 三类干扰分别怎么被解决

### 3.1 环境底噪 → 第一层 RNNoise + 训练侧噪声增广

RNNoise（GRU 降噪，几百 KB，流式 10ms 帧）消除平稳底噪。实测开销 0.061ms/帧、新增延迟 11.4ms。同时 PVAD 训练数据中 50% 样本叠加了 MUSAN 噪声与房间混响，模型本身对残余噪声鲁棒——双保险。

### 3.2 旁人说话 → 第二层 PVAD 声纹匹配（本方案的核心能力）

注册用户的声纹以 CAM++ 提取，切成多帧 token 序列存储。推理时，交叉注意力 + FiLM 双条件机制把"当前帧特征"与"注册声纹"做匹配，逐帧输出 P(目标说话人)：

- 旁人说话：P 值低 → 不触发任何行为，AI 继续说话、不被抢话
- 音色相近的旁人（最难 case）：训练时专门构造了 2000 条"易混淆硬负例"（干扰人从音色最接近注册者的 top-5 说话人中挑选），把误打断率压到历代最低

### 3.3 TTS 自身回声 → 第二层天然拒识（不需要 AEC）

本方案**完全不含 AEC**。关键洞察：TTS 的声音不是注册用户的声音，PVAD 对回声和对旁人说话一视同仁地拒识。实测 TTS 自回声（0.6 增益模拟）P(目标) 峰值 0.18，远离 0.5 阈值，零误触发——回声消除这个语音工程最著名的血泪问题（参考时钟对齐、漂移、收敛尾巴）被整体绕开。

### 3.4 双讲（用户和旁人/TTS 同时发声）→ PVAD 融合判别的主场

这是区分方案优劣的试金石。传统"声纹滑窗比对"在双讲时 embedding 被干扰人污染，漏打断率 64.8%（用户说话 AI 不停）。PVAD 的 GRU 直接学习"混合音中目标人说话"的融合特征：

| 方案 | 双讲漏打断 | 双讲误打断 | 正确率 |
|---|---|---|---|
| 声纹滑窗 + AS-norm（旧基线） | 64.8% | 0.0% | 35.2% |
| **PVAD v5（本方案，离线）** | **0.5–1.4%** | 2.5–5.6% | **93.0–95.0%** |
| **PVAD v5 增广环境（噪声+混响）** | 0.5–0.6% | 10.0–15.0% | **84.5–89.4%** |

## 4. 为什么不选传统方案

| 方案 | 问题 |
|---|---|
| AEC 回声消除 | 播放/采集参考时钟对齐、漂移、双讲收敛——工程血泪，且对旁人说话无效 |
| 声纹滑窗比对（cosine/PLDA） | 双讲时 embedding 被污染，漏打断 64.8%；阈值随设备环境漂移 |
| 唤醒词打断（"小×小×停止"） | 每次打断都要先喊唤醒词，打断路径长、不自然 |
| 语音分离（TSE/VoiceFilter） | 数据与训练成本高一个量级，且本方案已验证"不需要重建音频，只需要判定" |
| **PVAD（本方案）** | 免唤醒词、免 AEC、帧级流式、25-39 万参数 CPU 实时、0.029ms/帧 |

### 5.2 打断时序（实测延迟构成）

```
时间轴 ──────────────────────────────────────────────────►

TTS:   ████████████████ 播放中 ████████████│（停播）
用户:                                   ▲开口
                                        │
帧流:  ──┬──┬──┬──┬──┬──┬──┬──┬──┬──┬──┬──┬──  （10ms/帧）
             RNNoise(+11ms)│fbank│PVAD│P>0.5│P>0.5│
                                        └──┬──┘
                                     confirm=2 确认
                                        │
触发:  ────────────────────────────────► t≈开口+120ms（离线实测）
                                         实时端到端 150-300ms
```

延迟预算：RNNoise 11.4ms + 帧缓冲 10ms + PVAD 0.029ms/帧 + confirm 2 帧 20ms + 系统调度余量，
远低于人耳对"自然抢话"的感知阈值（约 500ms）。

### 5.3 体验要点

- **一次性注册（约 30 秒）**：引导式三段录音——正常距离念指定文本 → 离远 1 米念数字 → 自由发挥聊天。覆盖近讲/远讲/自然语体，声纹特征本地持久化，重启免注册
- **即时打断**：用户开口到 TTS 停播 150–300ms（帧级判别 + confirm=2 + RNNoise 11.4ms），低于人耳感知的自然停顿阈值
- **不打断时的行为**：旁人说话不会打断 AI，AI 继续说自己的；ASR 通路不受影响（可配置：是否将非目标语音也从 ASR 输入中屏蔽，实现"听觉层面"的彻底降噪）
- **隐私**：声纹特征（192 维 embedding，不可逆还原语音）本地存储，不出设备

## 6. 实测效果（C++ 生产管线，各 200 条双讲样本）

| 测试条件 | 漏打断（用户说话没反应） | 误打断（旁人/TTS 触发） | 正确率 |
|---|---|---|---|
| 干净环境 | 2.5% | **1.5%** | **95.0%** |
| 恶劣环境（噪声+混响） | 0.5% | 15.0% | **84.5%** |

模型规格：离线版 39 万参数（多帧注意力），实时版 26 万参数（FiLM + 流式 state 复用），纯 CPU 推理 0.029ms/帧，内存占用 MB 级。

## 7. 集成方案

接入点位于**音频采集之后、ASR/对话逻辑之前**，对现有对话系统零侵入：

```
现有系统改动清单：
1. 音频采集输出 → 接 PVAD 管线（C++ 库 / CLI 进程 / 参考 qt_demo）
2. 打断事件 → 接 TTS 停播接口
3. 首次使用 → 引导注册流程（参考 qt_demo 向导，可移植）
```

三种交付形态：

- **C++ 库**（`src/`）：直接链接进对话主程序，MinGW/MSVC 双工具链
- **CLI 进程**（`double_voice --mic --template tpl.bin`）：进程间集成，打断事件输出到 stdout
- **Qt 参考实现**（`qt_demo/`）：完整可运行的体验 demo，含注册向导、TTS 朗读、打断停播，可作为集成样板

部署矩阵（按环境选模型）：

| 场景 | 模型 | 说明 |
|---|---|---|
| 离线/批量处理 | `pvad_v5.onnx` | 多帧注意力，增广正确率 89.4% 历代最佳 |
| 实时·一般/恶劣环境 | `pvad_v4_stream.onnx` | 流式 state 复用，0.029ms/帧，生产默认 |
| 实时·稳定干净环境 | `pvad_v5s_stream.onnx` | 多帧条件，对音色相近干扰人更强 |

## 8. 已知边界（诚实清单）

- **音色极相近的人**（如直系亲属同性别）仍存在残余误打断可能——这是声纹技术的理论边界，工程上靠易混淆硬负例持续压制
- **恶劣环境误打断 15%**：主要发生在强噪声+混响+双讲叠加时；可通过提高确认帧数（confirm=3）或阈值进一步压制，代价是打断略肉
- **需要用户配合注册**：30 秒一次性流程，是"只有我能打断"这个承诺的必要前提
- **不替代 ASR 端降噪**：本方案解决"打断/行为"层面的噪音，ASR 识别率层面的降噪可复用同一管线输出做扩展

## 9. 落地路线

1. **体验验证**（现状已完成）：qt_demo 全功能 demo，注册→朗读→打断闭环，auto-test 全 PASS
